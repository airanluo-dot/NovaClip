# Media detection

Browser observations and parsing have separate owners. `BrowserPage` owns WebView2 COM calls and native controls. `BrowserMediaDetectionSession` owns navigation cancellation and a fixed reader budget (three network readers and one page-data reader). `BrowserPageContextGate` combines actual DOM source with the intended/authoritative page so an outgoing document cannot restore its old identity during navigation. `MediaDetectionCoordinator` owns the current page, normalized candidates and authoritative detection state; `BilibiliMediaIdentity` owns the shared identity rules.

A navigation derives BV/AV/episode and part number from the URI. Later CID/title/identifier enrichment for that same resource keeps the generation and ready media. A real BV/AV/CID/episode/part change retires the generation; URI changes from SPA navigation are observed before waiting for a bridge message. BV Base58 payload comparison is case sensitive. Responses must prove the current content and CID; network responses arriving before CID retain at most four normalized candidates until matching context arrives. Old-generation, conflicting wrapper identities and unrelated prefetched parts are rejected.

Network response parsing is an active `ObserveAsync` path, not an empty strategy placeholder. Page PlayURL globals and hydration data use `ObservePageDataAsync`. The bridge sends actual bounded playback data, validates wrapper identities, and exports a per-document nonce which the host checks against the current document before replaying context/media. After a SPA identity change, an identity-free old global cannot be rebound to the new route.

The bridge uses four finite route probes, a finite coalesced playback-event budget and at most one normal account-authorized API fallback per content identity. It does not forge WBI signatures, retry indefinitely, download in JavaScript or bypass account/DRM restrictions. Request bodies and page traversal are bounded. A 12-second native observation deadline ends missing evidence, while a later legitimate playback event can recover the state. Waiting, no media, parse failure, login/permission denial and unsupported DRM have distinct states/codes. Valid ready media survives a later transient failure.

Repeated equivalent results retain the same descriptor; updated signed URLs or track metadata can replace it. UI updates coalesce to the current authoritative snapshot; unchanged media does not rebuild quality controls. The download command uses the visible descriptor and checks it again after acquiring the browser request context. Cookie and user agent stay in memory. Media redirects are bounded to five hops; cross-host/port or HTTPS downgrade permanently removes Cookie/Authorization, and intermediate responses are disposed. DASH uses selected video/audio tracks; every DURL container is remuxed with FFmpeg before atomic output commit.

Diagnostics retain bounded non-sensitive state/generation/CID/event codes. Cookies, authorization values and signed media queries are excluded. Unit and JavaScript VM regressions verify ordering and resource rules; they do not substitute for real embedded-browser playback and completed-download acceptance described in `TESTING.md`.
